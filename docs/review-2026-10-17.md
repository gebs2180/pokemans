## Decisions for you (changes are in, please confirm or reverse)

1. **Grade 1 no longer gets an era 1-to-2 ratio.** Other cards' PSA 1 premiums were pulling the era ratio towards 1, which brought grade 1 sales into the pricing of other cards.
   - A grade 1 with no sales of its own now steps down from grade 2 using the era's **2-to-3** ratio. If there isn't one, it uses the card's own ladder.
   - Ladders flatten at the bottom, so this errs low. On the worked example it gives grade 1 = 85 × 0.78 = $66.30, the same as the methodology doc's $66.
   - This is recorded in CLAUDE.md and m3-progress 6a as "needs Zach's OK".
2. **Top-five cap: a bug fix that changes behaviour** (`PortfolioEvaluator`). Only the top five cards were scaled down. A card tied with the fifth, or just below it, then rejoined the top five and pushed it over 50%: six cards at 100 came to 340 against a 320 limit. Every other card is now held at or below the smallest scaled top-five value. Caps also round down to the cent now.
3. **Manual entries need a set release date** (Zach, 2026-10-18), and it can't be in the future. The identify form has a required date field. Undated cards that already exist are still flagged as a backstop: A holo or 1st Edition with no release date counts as VINTAGE_HOLO, and a chase rarity with no date counts as RECENT_CHASE. Before, they came out NONE, for example a hand-entered Base Set Charizard.

## Open methodology questions (nothing changed)

- **FLV is never above QSV** (decided 2026-10-18): FLV = min(formula, QSV). With the 1.0.0 parameters it can't happen anyway, because the depth discount is always at least d (the review's example was wrong), so the cap guards against future parameter sets.
- **Caps against the final base** (decided 2026-10-18): one cap level for every card, the highest that keeps each card at most 20% and the top five at most 50% of the capped base. Under 10 eligible cards the caps aren't applied and the trace says so (`portfolio.capsMinCards`). The correlation haircut still comes after the caps, so a capped card can end up slightly above 20% of the very final figure.
- **Grade-first lift charges grading cost twice:** FLV_raw is built from net prices, and C is then subtracted again. Is that intended? Either way it should be written into the doc.
- **The 90-day window spans 91 days**, because both ends are inclusive. Tests now pin this behaviour; change it if you meant exactly 90.

## Fixed

### Security (backend)
- **Decompression bombs.**
  - The new `storage/ImageGuard` reads the format and size from the header and refuses anything that isn't JPEG or PNG, or is over 100 MP or 16,000 px on a side, before ImageIO or OpenCV decode it.
  - It runs in `QualityChecker`, which covers photo confirm, and in `ImageResizer`, which covers the provider upload.
  - Tests: a PNG claiming 30000×30000 in about 30 bytes, GIF, BMP and TIFF refused, and a garbage fuzz loop.
- **Token audience.** The app refuses to start when an issuer is set without `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_AUDIENCES`. Before, it failed open and accepted any token from the tenant.
- **Invites.** Accept takes a row lock, so two people can't both use one invite.
- **Photo confirm:**
  - It checks contributor consent, as upload already did.
  - It locks the photo and then the card, so a double confirm is safe and `CaptureCompleted` fires exactly once when front and back are confirmed in parallel.
  - The membership check now runs before the card lookup, so outsiders can't probe card ids.
- **Manual comps:**
  - Only http/https listing URLs are accepted.
  - Prices are limited to 10 digits and 2 decimals, so oversized values get a 400 instead of a 500.
  - An eBay listing is keyed by its item number, so the same sale pasted with different tracking parameters is refused as already recorded.
  - A race on the unique key returns 409.
- **Config toString** no longer prints API keys or the storage secret.
- **V11 migration:**
  - Adds the database `refuse_update` trigger to `provider_prediction`, `consent_record`, `grade_outcome`, `outcome_verification` and `card_identification`. Deletes are still allowed, for data-deletion requests.
  - Adds the missing FK and lookup indexes.

### Correctness (backend)
- **Card recognition.** The Claude reading now commits before catalog matching. A TCGdex outage used to roll the reading back and re-run the paid read every 15 seconds, forever. A matching failure is now recorded on the reading.
- **Predictions.** The assessment rebuild runs in its own transaction, so a failed rebuild can't roll back a stored provider prediction.
- **Polling deadline.** A request stuck "pending" at a provider fails after 24h (`pokemans.condition.worker.max-pending`).
- **UTC.** The authenticity date check now uses UTC.

### valuation-core
- **Interpolation never prices a grade above the grade over it.** Before, out-of-order anchors such as 8 at $500 and 10 at $400 put 9 at $447.
- **Card confidence counts sales before outlier trimming**, matching decision 3.
- **The derived-price confidence drop** checks the stress shift that actually applies: 3 grades at C or D.
- **Validation:**
  - Ratios must be above 0 and at most 1.
  - Negative σ, negative sales a month and fewer than 1 copy are refused.
  - `Volatility.monthly` refuses a zero price.
  - Clear null errors on the inputs.
- **Volatility.fromComps** refuses raw (U) sales.
- **Duplicate card ids** in a portfolio are refused instead of silently overwriting each other.

### Web
- **Links.** `safeHref` means only http/https links are rendered.
- **API paths.** Every API path is URL-encoded through `apiPath`, which closes client-side path traversal from route params.
- **Double submit.** Busy flags on every create and verify form stop double submits from creating duplicate comps or orgs.
- **Dates.** The sold-date default uses the local date. It was UTC, which gives tomorrow's date on US evenings.
- **Session loss:**
  - A lost session (a 401, or the Auth0 errors `login_required` and `missing_refresh_token`) goes back to login and then returns to the same page.
  - The redirect happens at most once a minute, so a backend that rejects every token can't cause a redirect loop.
- **Response bodies.** An empty 2xx body is no longer a JSON parse error.
- **useLoad** resets when its deps change, so the previous card no longer shows while the next one loads.
- **Suggestions.** Confirming one sends the card's own provider. It always sent TCGDEX before.
- **Grade input.** The contributor grade is a number input, so NaN is no longer saved as null.
- **Smaller fixes:**
  - Stale errors are cleared.
  - Clipboard failures are handled.
  - aria-labels and `role="alert"` are added.
  - Admin and review pages are lazy-loaded, and vendor code is in its own chunk, which removes the 500 kB warning.
- **Lint.** `react/exhaustive-deps` is on.

### CI and supply chain
